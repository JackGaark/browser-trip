dns lookup

A name becomes a number

Networks route by IP address, not by name. To find example.com, the browser first checks answers it already remembers. If those miss, a recursive resolver walks the naming tree for it, from the root servers down to the domain’s own.

Press Resolve. The host name comes from the address you entered in scene 1.

    tcp + tls handshake

    Shaking hands before saying anything

    A new connection costs round trips before the first byte of the page arrives. TCP agrees to talk. TLS agrees on encryption keys and proves the server is who it claims to be. Only then does the request go out.

    240 ms
    3 round trips before the first byte of the page.

    http/2: many streams, one connection

    Ten files, one pipe

    The HTML arrives first and names nine more files. HTTP/1.1 can carry only one response at a time per connection, so browsers open up to six connections per site, each with its own handshake, and queue the rest. HTTP/2 interleaves every file as streams over the one connection it already has.

    • html
    • css
    • js
    • font
    • image
    • queued

    Simulated with a 40 ms round trip and a 12 Mbps link. c1–c6 mark which HTTP/1.1 connection carried each file.

    parse html into the dom

    Text in, tree out

    The bytes arrive as plain text. A tokenizer reads it into start tags, end tags and text, and a tree builder turns those into the DOM, the live tree that JavaScript works with. It is forgiving: leave out <html> or <body> and it quietly adds them.

    Amber dashed nodes were added by the parser because they weren’t in your source.

    scripts can pause the parser

    One script tag can stop everything

    When the parser meets a script, it has to decide whether it may keep reading. A plain script could rewrite the page as it runs, so the parser waits. Two attributes change that.

    paint: a list of draw calls
    
      
    Painting is a to-do list
    
      
    Paint doesn’t produce pixels yet. It records an ordered list of drawing commands, called a display list: fill this rectangle, draw this text, place this image. Order matters, because later commands land on top.

      raster: tiles in parallel
      
      
      Pixels, one tile at a time
      
      
      Each layer is cut into tiles, and several raster workers fill them in parallel, nearest the viewport first. Scroll faster than they can keep up and you see blank checkerboard tiles for a moment.
      
      
      Then the compositor, running on the GPU, stacks the finished tiles into a frame. On a 60 Hz screen it gets 16.7 ms to do that, every single frame.

      v8: from source to machine code
      
      
      JavaScript gets faster the more it runs
      
      
      Engines start by interpreting bytecode, which starts quickly but runs slowly. Code that runs often gets recompiled by faster tiers, which bet on the types they have seen. Break that bet and the engine bails out, or deoptimizes, back to the start.
      
      
      
        
        
        
        
      
      
      
      
      
      
      
      Tiers are V8’s. Thresholds, speeds and the machine code shown are illustrative; real engines decide from runtime feedback.

        garbage collection
        
      
        Memory tidies up after itself, mostly
        
      
        Every object your code creates takes memory. The garbage collector starts from the roots, such as global variables and the current call stack, follows every reference, and frees whatever it can’t reach. Most objects die young, so V8 sweeps a small nursery often and promotes survivors to an old generation that it checks less often.
        
      
        
        
        
      
        
      
        
        
        
      
        
      
        
      
        
    
        
    
        
      
        
      
        Objects that survive two nursery sweeps get promoted to the old generation. Green outlines mean “reachable”.
        
    
        
  
        

        



        
  
        
    
        
      
        one browser, many processes
        
      
        Every site gets its own walled house
        
      
        A modern browser is a small town of processes. The browser process runs the window and tabs, a GPU process draws, and a network service fetches. Each site gets its own sandboxed renderer process, so a crash, or an attack, in one can’t reach the others. Even an iframe from another site gets a separate one.
